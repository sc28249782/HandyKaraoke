# P1b — Runtime Staging Baseline

This document defines the disposable staging layout used for recovery smoke
tests. It is based on the HandyKaraoke 2.4.1 Windows x64 installation observed
on 2026-09-16, but it does not claim compatibility for every legacy feature.

## Why stage before testing

A build directory is a developer artifact. It can silently use DLLs, settings,
or the working directory from the source checkout. Tests must instead start
from a separate folder that has only the files the application is expected to
ship.

## Create a Release-stage folder

From an x64 Native Tools Command Prompt for VS 2022:

```bat
cmake -S . -B build\msvc-x64-release -G Ninja ^
  -DCMAKE_BUILD_TYPE=Release ^
  -DCMAKE_PREFIX_PATH="E:\Qt\5.15.2\msvc2019_64"

cmake --build build\msvc-x64-release --target stage-runtime --parallel
```

The default destination is:

```text
build\msvc-x64-release\stage\HandyKaraoke
```

Override it only with an empty, disposable directory:

```bat
cmake -S . -B build\msvc-x64-release -DHK_STAGE_DIR="E:\Stage\HandyKaraoke"
```

The target never copies songs, SoundFonts, VST plug-ins, or user configuration.

## Expected layout

```text
HandyKaraoke\
  HandyKaraoke.exe
  Qt and legacy audio runtime DLLs
  platforms\
  sqldrivers\
  languages\en.qm
  Style.ini
  Songs\
    KAR\
    NCN\
      Song\
      Lyrics\
      Cursor\
    HNK\
  SoundFonts\
  VST\
```

Qt plug-in folders are generated by `windeployqt`. The exact optional folders
depend on the selected Qt kit and its detected dependencies.

## Compatibility boundaries

- `Songs\HNK` is created only to preserve the historical folder layout. HNK
  scanning and playback remain disabled in this fork.
- `SoundFonts` and `VST` are empty user-content locations. Do not add
  copyrighted or unlicensed files to the repository or release archive.
- The historical `VSTChecker_x64.exe` is intentionally not staged. It is an
  old helper built with a different toolchain and must be rebuilt or replaced
  before legacy VST scanning is enabled.
- Auto-update, an installer, the Visual C++ runtime, and media migration are
  packaging work for P3; they are not implied by a successful P1b stage.

## P1b smoke-test entry point

Run only this executable for the next tests:

```text
build\msvc-x64-release\stage\HandyKaraoke\HandyKaraoke.exe
```

Record missing files, configuration behavior, and MIDI/SoundFont findings in
the work queue before modifying the application.
